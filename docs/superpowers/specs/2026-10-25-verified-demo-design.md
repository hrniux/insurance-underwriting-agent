# AI 开源项目筛选与核保 Demo 验证设计

用户已授权直接决定并完成推荐 Demo，20 个项目使用 Star 收藏。

## 目标与验收

基于 hrniux/insurance-underwriting-agent 当前 main，交付可在 Mac/Linux 用一条命令复现的离线核保演示。沿用现有 Java 21/Spring Boot 应用及中文页面；使用 Mock 模型和虚构数据，零模型 Key，不声称验证过真实 LLM 的质量。

新增启动脚本构建应用、启动独立的本地进程、等待健康、执行验收并停止自有进程。默认端口18080，端口被占用时明确失败，不能误验另一服务。超时有界，失败退出非零且保存失败证据。支持现成服务的独立验证命令。

验收脚本使用 Python3 标准库，对真实 HTTP API 验证四个场景的固定预期：P-1001 MANUAL_REVIEW/HIGH/70，P-2001 APPROVE/LOW/10，P-3001 MANUAL_REVIEW/MEDIUM/40，P-4001 REJECT/HIGH/60。验证七步轨迹、六个工具轨迹、知识与 Prompt/规则指纹、Mock 路由；同键同参幂等重放、同键异参409；RAG黄金集Recall@4和MRR达到1；决策重演STABLE；报告包含已保存结果。每次运行使用不同幂等键。

原始API响应与summary.json写入target/demo-evidence/<run-id>，通过标识必须依赖所有断言实际通过。报告记录UTC时间、Git提交和实际模型来源。不得将凭据写入报告。

新增20个仓库机器可读清单和中文研究文档，说明选型标准、许可证、用途和限制；Star完成结果在研究文档中如实记录。不是声称遍历所有GitHub仓库，也不是绝对排行榜。

## 方案选择

1. 推荐且采用：在已有离线Demo上增加可执行验收与证据。成本低，能稳定检查规则、检索和审计契约。
2. 真实Mac模型：Ollama替换Mock，需要用户本机模型与内存，另行验证模型输出，不作为本次默认路径。
3. 新建Python应用：会重复已有核保逻辑，不利于复用现有Java仓库，故不采用。

## 边界

不改业务判断、依赖版本及现有页面；不合并main、不部署公网。通过独立分支与draft PR交付，保留原始验证结果。模型能力、真实保险决策、Mac本机运行均不在本次已实测声明范围内。
